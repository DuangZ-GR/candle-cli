# v0.3.1 Stability Hardening Design

**Date:** 2026-05-09

## Goal

Harden the new v0.3.0 minimal agent loop so it is safer and more reliable for real use. The focus is not adding new agent features, but tightening workspace boundaries, making shell execution predictable, preventing session ID collisions, and documenting a real-model smoke-test path.

## Confirmed Scope

### In scope

- Make tool execution workspace-root aware.
- Restrict `read`, `glob`, `grep`, and `edit` to the active workspace root.
- Reject direct path traversal and symlink escape outside the workspace.
- Run `shell` commands from the workspace root.
- Add shell timeout support with a simple environment override.
- Make session IDs much less collision-prone.
- Strengthen parser/loop behavior for malformed tool-call recovery and mixed text around tool-call blocks.
- Add tests for path escape rejection, shell cwd/timeout, parser recovery, and session ID uniqueness.
- Add documentation for a real bridge-runtime smoke test.

### Out of scope

- Interactive permission confirmation.
- Native OpenAI `tools` schema.
- Full sandboxing or process isolation.
- Streaming.
- Long-lived Python worker reuse.
- New tool types.
- Richer diff UI or confirmation prompts.

## Recommended Approach

The recommended design is to keep the current architecture but move all path-sensitive behavior behind a workspace-aware `ToolRegistry`. The registry becomes the place that resolves, validates, and normalizes file paths before handing off to tool implementations.

This avoids duplicating security checks inside each individual tool implementation and keeps the tools simple. The agent loop stays unchanged at a high level: model emits a tool call, Rust executes it, tool results go back into the session, and the model continues.

## Workspace Boundary Model

Each CLI session already has a `workspace_root`. v0.3.1 should make `ToolRegistry` carry that root explicitly.

Recommended API shape:

```rust
ToolRegistry::read_only(workspace_root: impl Into<PathBuf>)
ToolRegistry::workspace_write(workspace_root: impl Into<PathBuf>)
```

The existing `default_read_only()` and `default_workspace_write()` constructors may stay temporarily as wrappers around `std::env::current_dir()` if needed for compatibility, but prompt mode and REPL mode should use the explicit workspace-root constructors.

### Path resolution rules

For `read`, `glob`, `grep`, and `edit`:

1. Accept relative paths and interpret them relative to `workspace_root`.
2. Accept absolute paths only if they resolve inside `workspace_root`.
3. Canonicalize the resolved target.
4. Reject the path if canonicalization shows it escapes the workspace.
5. Return a clear error message such as:

```text
path escapes workspace: ../../secret.txt
```

This includes symlink-based escape. If a path inside the workspace is a symlink to a target outside the workspace, it must be rejected.

## Tool Behavior Changes

### `read`

No behavior change beyond workspace path enforcement. Reads still return UTF-8 text.

### `glob`

The current implementation supports a very small subset of patterns. v0.3.1 does not expand feature scope here. Instead, it enforces workspace boundaries before evaluating the pattern and ensures returned matches stay within the workspace.

### `grep`

`grep` should walk only inside the workspace-validated root path. If the requested search path escapes the workspace, return an error instead of searching.

### `edit`

`edit` already enforces exact-one replacement from v0.3.0. v0.3.1 adds workspace path enforcement before the file is opened.

### `shell`

`shell` must execute with:

```rust
.current_dir(workspace_root)
```

This guarantees commands run from the active project root instead of whatever process directory happens to be current.

`shell` should also enforce a timeout. The recommended default is 30 seconds, configurable via:

```text
CANDLE_CLI_SHELL_TIMEOUT_SECS
```

If the command exceeds the timeout, terminate it and return an error like:

```text
command timed out after 30s
```

The timeout implementation should stay dependency-light if practical. A straightforward `spawn` + polling + `try_wait` loop is acceptable for this version.

## Session ID Hardening

Current session IDs use only Unix seconds:

```text
session-<seconds>
```

That can collide when multiple sessions are created in the same second. v0.3.1 should switch to:

```text
session-<unix_millis>-<pid>
```

This avoids adding a UUID dependency while substantially reducing collision risk.

## Tool Call Stability

The text protocol remains unchanged:

```text
<tool_call>{...}</tool_call>
```

### Mixed text handling

If the model emits explanatory text before or after a valid tool-call block, the parser should still extract the first valid block. This is more robust against imperfect real-model output.

### Malformed block recovery

The current loop already appends a correction message on malformed tool calls. v0.3.1 should keep this behavior but test it explicitly. The model should get one clear correction message telling it to retry with exactly one valid block or produce a final answer.

## Testing Strategy

### Tool registry / path boundary tests

Add tests that verify:

- `read` rejects `../../...` paths.
- `edit` rejects paths outside the workspace.
- `grep` rejects a search root outside the workspace.
- `glob` does not return matches outside the workspace.
- symlink escape is rejected where the platform supports symlink creation.

### Shell tests

Add tests that verify:

- `shell` runs inside the workspace root (`pwd` output matches tempdir workspace).
- `shell` returns timeout errors for long-running commands.
- timeout env var override is honored.

### Session tests

Add a test that creates multiple sessions back-to-back and confirms their IDs differ.

### Parser / loop tests

Add tests that verify:

- parser extracts a valid tool call even when wrapped by surrounding text.
- malformed tool call causes a correction message and a later successful final answer.

### Full verification

Before pushing, continue to require:

```bash
python3 -m pytest python/test_bridge_runtime.py -q
~/.cargo/bin/cargo test
~/.cargo/bin/cargo fmt --check
~/.cargo/bin/cargo clippy --all-targets --all-features -- -D warnings
```

## Documentation

Add a short smoke-test section showing how to manually test the real bridge runtime with Ollama or another OpenAI-compatible backend:

```bash
export CANDLE_CLI_RUNTIME=bridge
export CANDLE_CLI_API_BASE_URL="http://localhost:11434/v1"
export CANDLE_CLI_API_KEY="ollama"
export CANDLE_CLI_MODEL_ID="qwen2:0.5b"

cargo run -- prompt "读取 README.md，总结如何运行项目"
```

The docs should explain that expected behavior is:

1. model emits a `read` tool call,
2. Rust executes it,
3. model summarizes the file content.

## Acceptance Criteria

v0.3.1 is complete when:

- file tools cannot escape the workspace root,
- shell runs from the workspace root,
- shell timeout works and is tested,
- session IDs no longer collide under same-second creation,
- malformed tool-call recovery is tested,
- parser handles surrounding text around a valid tool call,
- smoke-test instructions exist in docs,
- full verification passes.

## Deferred Follow-up Work

After v0.3.1, the likely next steps are:

- interactive permission prompts,
- richer shell policy and command allow/deny controls,
- OpenAI-native tool schema,
- streaming,
- long-lived bridge worker,
- better edit/diff UX.
